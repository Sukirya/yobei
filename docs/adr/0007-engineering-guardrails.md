# ADR-0007：工程护栏——规格、ADR 与 CI 门禁

- **状态**：已采纳
- **日期**：2026-11-01
- **决策者**：Sukirya
- **参考**：`awesome-architecture/tutorial/08`、`14`、`23`、`24`

## 背景 / 上下文

架构约束如果只存在于聊天记录和某个人的记忆里，会在下一次重构、下一次 AI 生成代码、
下一次"赶时间"时悄悄消失。本项目由一个人维护并大量使用 AI 辅助，风险更高：
AI 默认只产出乐观路径，你没写下的约束它就当作不存在。

旧仓库还存在具体的工程卫生问题：

- 许可证自相矛盾（核心 GPL-3.0-or-later，前端 package.json 为 MIT，根目录没有 LICENSE）；
- Tauri 模板残留（`description = "A Tauri App"`、`authors = ["you"]`）；
- 四个"假端口"、若干死代码与死文档；
- CI 只跑核心测试与 Windows 编译检查，没有格式、lint、前端类型检查、Worker 测试；
- 架构决策只写在 DESIGN 的一节里，且部分已被后续讨论推翻。

## 决策

### 1. 规格金字塔（三层，缺一不可）

| 层 | 文件 | 管什么 | 读者 |
|---|---|---|---|
| ADR | `docs/adr/NNNN-*.md` | 为什么这么定、放弃了什么 | 人 + AI |
| 常驻规则 | `AGENTS.md`（Claude Code 同时读取 `CLAUDE.md`） | 做什么 / 不做什么，带反例 | AI |
| 适应度函数 | CI 与测试 | 红线，违反即失败 | 机器 |

**能下沉到更低一层的约束，就不停在上层。**

### 2. 许可证

- 全仓统一 `GPL-3.0-or-later`：核心 crate、Tauri 壳、前端、Worker、文档。
- 根目录提供 `LICENSE`。
- `package.json`、`workers/sync/package.json`、`src-tauri/Cargo.toml` 的 license 字段统一。

### 3. CI 门禁

每次 push 必须跑：

- `cargo fmt --check`
- `cargo clippy -- -D warnings`
- 核心测试
- `bun run check`（svelte-check）
- Worker 的 TypeScript 类型检查与测试
- 依赖审计（Rust 与 JS）
- 许可证与机密扫描（禁止把密钥提交进仓库）

### 4. 适应度函数（架构约束自动化）

| 约束 | 检查方式 |
|---|---|
| 核心不依赖任何平台/框架 | 核心 crate 的依赖白名单检查 |
| 线上报文与日志不含明文 | 协议测试：同步报文、错误信息、日志中不出现条目明文字段 |
| 条目类型恰好四种 | 格式/协议测试断言类型枚举 |
| 删除是终态 | 回归测试：迟到更新不能复活墓碑 |
| 服务器不能回滚内容 | 回归测试：清单版本与密文内版本不一致必须拒绝 |
| Secret Key 承重 | 回归测试：缺 SK / 错 SK 无法解开引导包与库 |
| 自动填充只认精确域名 | 匹配测试：包含/后缀匹配必须失败 |

### 5. 仓库形态

- 继续保持"核心 crate + Tauri 壳 + Worker"的单仓结构，不引入 workspace（Tauri 与 Android
  生成目录会让 workspace 路径变复杂，收益不足）。
- 用脚本（`scripts/` 下的 shell / 交叉平台命令）收敛格式化、检查、测试、构建命令。
- 删除四个未被使用的端口（`VaultStoragePort`、`RandomPort`、`ClockPort`、`KeychainPort`），
  或在补齐实现前不保留空接口——**死接口比没有接口更误导人**。
- 删除死代码与死文档；`docs/DESIGN.md` 顶部标注已被 ADR 取代的部分。

### 6. 变更纪律

- 涉及数据格式、密钥层级、同步协议、删除语义的改动，必须先新增 ADR。
- 每个 ADR 记录"考虑过的其它选项"，否则等于没有做取舍。
- 技术债要有意识地借、记录、安排偿还时机；无记录的技术债视为缺陷。

### 7. 开发环境注记

- Windows + Git Bash 下，`/usr/bin/link` 会遮蔽 MSVC 的 `link.exe`，导致 `cargo build`
  报链接错误。解决方式是调整 PATH 或使用 PowerShell / VS 开发者命令行。写入 README。

## 考虑过的其它选项

| 选项 | 否决原因 |
|---|---|
| A. 只写 ADR，不做 CI 门禁 | 文档靠自觉；最容易被违反的约束恰好是机器能检查的那些。 |
| B. 只做 CI，不写 ADR | 机器能验证"做了什么"，验证不了"为什么"；后人会误删必要的复杂度。 |
| C. 迁移到 Cargo workspace | 对当前单核心 + 单壳结构收益低，Android 生成目录增加复杂度。 |
| D. 保留空端口以"预留扩展" | 空接口不会保护未来，只会让读者误以为存在可替换实现。 |

## 取舍与后果

**得到：**

- 约束在 AI 每次生成代码时自动生效，而不是靠人记得。
- 架构腐化在 CI 阶段被拦住，而不是在半年后的重构里发现。
- 许可证与仓库元数据一致，不再自相矛盾。

**付出：**

- CI 时间增加；每次改动都要面对更严格的检查。
- 写 ADR 与维护 AGENTS.md 是持续成本。
- 删除空端口意味着将来真正需要时再设计，而不是现在就预留。

## 未决问题

- Worker 端测试框架的选择（Vitest + Miniflare 或 Wrangler 的测试模式）。
- CI 中 Android 构建耗时较长，是否改为按路径触发。
