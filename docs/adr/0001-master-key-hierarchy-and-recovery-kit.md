# ADR-0001：密钥层级、强制 Secret Key 与恢复套件

- **状态**：已采纳
- **日期**：2026-11-01
- **决策者**：Sukirya
- **取代**：`docs/DESIGN.md` §3 中"Secret Key 可选"的表述

## 背景 / 上下文

yobei 是自部署、零知识、离线优先的密码管理器，Android 一等。它必须同时满足三条看似冲突的要求：

1. **新设备必须能独立重建保险库**：旧设备可能在丢失、损坏、被盗等不可抗力中不复存在。
2. **服务器（用户自己的 Cloudflare 账号）不可信**：它不能读明文，不能改暗文，也不能通过任何形式离线验证主密码的猜测。
3. **同步服务器只存密文**：新设备连"库头"（KDF 参数、盐、被包裹的库密钥）都拿不到。

旧 demo 的 Secret Key 是可选的，服务器也不存任何引导信息。结果是：新设备只能靠"复制整个库文件"才能加入；而一旦让服务器保存可解读的引导信息，服务器就同时拿到了离线验证密码的旁路。

## 决策

1. **密钥层级**（全部使用经过审计的库，不自研密码算法）：

   ```
   主密码 + 强制 Secret Key
     └─ Argon2id(盐, 参数来自库头) ──► master
          └─ HKDF-SHA256(salt = Secret Key, info = "yobei-kek-v1") ──► KEK
               └─ XChaCha20-Poly1305 包裹 ──► Vault Key（每库随机 32 字节）
                    └─ HKDF-SHA256(info = "yobei-entry-v1:<entry_id>") ──► 逐条目密钥
                         └─ XChaCha20-Poly1305，AAD = entry_id ──► 条目密文
   ```

2. **Secret Key 强制开启，不可关闭、不可更换**。32 字节，以分组 base32 展示。
   它不参与同步，只保存在设备安全区（Android Keystore / Windows DPAPI / macOS Keychain）
   和用户的恢复套件里。

3. **派生域分离**：每个用途使用不同的 HKDF `info`（`kek` / `bootstrap` / `auth` / `entry` / `export`），
   禁止跨用途复用同一份派生结果。

4. **KDF 参数随库头存储**，默认 `memory_kib = 64 MiB, t = 3, p = 1`；下限为 OWASP 的
   `19 MiB, t = 2, p = 1`。读取任何不可信的库头或加密导出文件时，必须校验参数上限
   （`memory_kib ≤ 1 GiB`、`t ≤ 10`、`p ≤ 8`），防止恶意文件触发内存耗尽。

5. **恢复套件（Recovery Kit）** = Secret Key + 同步地址 + 使用说明。
   - 创建保险库时一次性生成，强制用户确认"已保存"。
   - 创建 7 天后抽查 Secret Key 中的 4 个字符，确认用户真的保存了。
   - 恢复套件可打印/存离线；不以明文形式进入日志、遥测或同步报文。

6. **丢失 Secret Key 且没有任何已授权设备 = 永久不可恢复**。这是零知识的必然代价，
   产品与文案必须明确说明，不能暗示"官方可以协助找回"。

7. **修改主密码只重新包裹 Vault Key**，不重新加密任何条目；同时生成新的 KDF 盐。
   修改 Secret Key 不在 v1 范围内——它等价于重建保险库。

## 考虑过的其它选项

| 选项 | 否决原因 |
|---|---|
| A. Secret Key 可选 | 服务器一旦持有可解读的引导包，就能离线验证密码猜测，破坏零知识承诺。 |
| B. 不保存引导包 | 新设备无法加入，只能复制库文件；不可抗力场景直接失效。 |
| C. 旧设备审批新设备 | 依赖旧设备，恰好是"旧设备没了"时最需要恢复的场景。 |
| D. 密码派生一切、不要 Secret Key | 与"服务器不能离线验证密码"冲突；自部署服务器被拿走的风险不可接受。 |
| E. 社交恢复 / 应急联系人 | 有价值，但需要额外的信任与协议设计，推迟到后续 ADR。 |

## 取舍与后果

**得到：**

- 服务器（或拿到服务器数据库的人）即使拥有全部密文与引导包，也无法离线验证任何密码猜测。
- 新设备只需要"主密码 + 恢复套件"，不依赖旧设备。
- 修改主密码成本极低，不触碰条目数据。

**付出：**

- 用户必须妥善保存恢复套件；丢失即永久失去，没有后门。
- 旧 demo 保险库无法迁移（本项目尚无真实用户数据，接受）。
- Secret Key 不可轮换；将来若需要轮换，必须走"重建保险库 + 重新同步"的专门流程（未决）。
- 每次新设备加入都需要手工输入或扫描恢复套件，不能"扫码登录"式一键完成。

## 未决问题

- Secret Key 轮换方案（是否需要、如何在多设备间安全轮换）。
- 恢复套件的可访问性形式（打印纸、二维码、离线文件），以及防止用户把它截图存进相册的引导。
