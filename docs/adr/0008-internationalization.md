# ADR-0008：国际化（i18n）与用户可见文字

- **状态**：已采纳
- **日期**：2026-11-01
- **决策者**：Sukirya
- **依赖**：ADR-0003（冲突副本）、ADR-0004（条目模型）

## 背景 / 上下文

项目希望支持多语言界面（首期：英语、简体中文）。但当前代码里有三类"文字"混在一起：

1. 界面文案（按钮、提示、空状态）。
2. 核心返回给界面的**句子**：密码强度警告、部分错误信息。
3. **被写进数据**的文字：冲突副本的标题后缀 `(conflict copy)`。

第 2 类把"展示层"的职责漏进了核心；第 3 类更严重——一旦写进数据，就会随同步传到所有设备，
并且永远停留在创建时的语言，之后无法翻译。i18n 不只是"把字符串抽出来"，必须先划清边界。

## 决策

### 1. 用户可见文字只属于展示层

- 核心与数据模型**不返回、不存储**某一种语言的句子。
- 核心返回稳定的 code / 结构化值；界面负责翻译与格式化。
- 这条规则同时适用于桌面端（Svelte）、Android（Kotlin 资源）与将来的浏览器扩展。

### 2. 核心的结构化输出

- 密码强度：`StrengthReport.warnings: Vec<WarningCode>`，`WarningCode` 是带 `code` 标签的枚举
  （`empty` / `common_password` / `common_word { word }` / `sequence` / `repeated_characters` / `year`）。
- 破解时间：核心只返回 `offline_crack_seconds: f64`，由界面按当前语言格式化。
- 数据模型不存储本地化标签。

### 3. 冲突副本不再改写标题

- `Entry.conflict_copy_of: Option<String>` 标记它是哪条条目的冲突副本。
- 条目标题保持原样；"(conflict copy) / 冲突副本"由界面渲染为徽标。
- 这样同一份数据在任何语言下都能正确显示，旧的英文后缀也不会被同步出去。

### 4. 语言选择与回退

- 支持的语言：`en`、`zh-CN`（首期）。
- 顺序：用户在本机的选择 → 操作系统语言 → 英语。
- 选择保存在本机（`localStorage`），**不进入保险库**：语言是设备偏好，不是需要同步的数据。
- 切换语言立即生效，并更新 `<html lang>`、数字与日期格式（`Intl`）。

### 5. 字典与类型约束

- 前端字典按扁平 key 组织，英语字典是类型来源：
  `type MessageKey = keyof typeof en`，其他语言字典必须实现同一组 key（编译期检查）。
- 缺少 key、拼写错误、语言间 key 不一致都会在类型检查阶段失败。
- 插值使用 `{name}` 占位符；数字先经 `Intl.NumberFormat` 格式化再插入。

### 6. 分阶段迁移（技术债，明确记账）

- **已落地**：界面文案、密码强度 code、冲突副本标记、破解时间数值。
- **未落地**：Tauri 命令的错误仍是核心返回的英文 `String`，界面原样显示。
  完整的做法是引入 `CoreError`（`code + params`）并让每个命令返回它；
  这涉及核心所有 `Result<T, String>`，作为独立重构排期。
- 触发条件：当需要本地化的错误超过 5 类，或 Android 端需要复用同一套错误码时，启动该重构。

## 考虑过的其它选项

| 选项 | 否决原因 |
|---|---|
| A. 只在前端替换子弹，核心继续返回英文句子 | 核心错误、强度警告无法翻译；违反"核心可移植"的边界。 |
| B. 把翻译文件放进核心 / 服务端 | 核心不应知道 UI 语言；服务端更不该参与展示。 |
| C. 用 `gettext` / Fluent / ICU MessageFormat | 对两种语言、几十个 key 的规模过重；将来需要复数/性别规则时再评估。 |
| D. 在标题里写本地化后缀 | 数据被语言焊死，跨设备无法翻译，且同步后会扩散。 |
| E. 语言选择存进保险库并同步 | 语言是设备偏好；同步会让手机和电脑互相覆盖。 |

## 取舍与后果

**得到：**

- 加一种语言只需要新增一份字典，核心与数据零改动。
- 冲突副本在任何语言下显示正确；数据的含义与展示解耦。
- 密码强度警告可以被测试断言（断言 code，而不是句子）。

**付出：**

- 核心与界面之间多了一层 code 映射；新增警告类型要同时改核心、字典和映射。
- 命令错误暂时仍是英文；在完整 `CoreError` 落地前，这一部分不满足"全量本地化"。
- 每种语言都要维护完整的 key 集合（由类型检查兜底）。

## 未决问题

- 复数规则与 RTL 语言（首期不需要）。
- Android Credential Provider 的活动页文案（使用 Android 资源，遵循同一套 locale）。
- 是否允许用户覆盖"跟随系统"以外的默认语言；当前默认跟随系统。
