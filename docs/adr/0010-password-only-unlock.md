# ADR-0010：日常解锁只用主密码

- **状态**：已采纳
- **日期**：2026-11-01
- **决策者**：Sukirya
- **依赖**：ADR-0001（密钥层级）、ADR-0002（新设备加入）、ADR-0009（生物识别解锁）
- **取代**：ADR-0001 中“解锁强制要求 Secret Key”的表述（仅解锁路径；新设备加入与恢复仍强制）

## 背景 / 上下文

Secret Key 是一串 26 位随机字符，是恢复套件的一部分：写下来收好，
新设备才用。但当前 `Vault::open` 每次解锁都强制要求它，用户每天要
输一长串记不住的字符——这是 ADR-0006 阶梯没有落地的另一个表现，
和生物识别缺失是同一个根。

1Password 的做法是参考：Secret Key 只在新设备上要一次，日常解锁
只用主密码（生物识别是更顺的那档，见 ADR-0009）。

## 决策

### 1. 第二份包装：同一把 Vault Key，两份 KEK 包装

- 库头新增 `wrapped_vault_key_password_only`（可选字段，老库头没有它）：
  Vault Key 用**只由主密码推导的 KEK**再包一份。
  只由密码的 KEK 就是 Argon2id 的直接输出（`derive_kek` 传 `None`），
  不经过 HKDF、不碰 Secret Key。
- 解锁分两条路：
  - 给了 Secret Key：走原来的“密码 + Secret Key”包装（行为不变）；
    若密码-only 包装缺失，顺手写好（迁移，见 §2）。
  - 没给 Secret Key：走密码-only 包装；包装不存在时报错，
    提示需要 Secret Key 解锁一次以启用；密码错时报密码错误。
- 两份包装互相独立：密码-only KEK 是“密码 + Secret Key”那条路的
  HKDF **输入**，HKDF 单向，所以攻破密码-only 包装得不到
  Secret Key 那条路的 KEK；反过来，只拿到 Secret Key 也打不开
  （仍需密码）。Vault Key 本身只有一把，条目加密不变。

### 2. 迁移：第一次带 Secret Key 的解锁顺手完成

- 老库头没有密码-only 包装：更新后第一次用密码 + Secret Key 解锁时，
  `open` 写好这份包装并保存库头；此后只输密码就能开。
- `create` 与 `adopt` 直接写两份包装：新库与新加入的设备
  从一开始就支持仅密码解锁。
- `change_password` 两份一起重包（新盐 → 两个 KEK 都变），
  Vault Key 不变（ADR-0001），生物识别 blob 不受影响（ADR-0009）。

### 3. Secret Key 的位置不变

- 引导包（bootstrap）仍只含 Secret Key 那份包装：新设备加入、
  恢复、同步地址推导仍强制 Secret Key（ADR-0002 不变）。
- Secret Key 永远不落盘、不进第二份包装、不参与日常解锁的推导。
- 改主密码、导出、管理设备等管理操作仍要主密码（ADR-0006 §4 不变）；
  本次只改“开锁要不要 Secret Key”，不引入会话模型（见 ADR-0009 §6）。

### 4. 代价：本地库文件的安全现在只剩主密码

- 拿到库文件的人可以直接对密码-only 包装做离线猜测（Argon2id
  按次计费），不再需要 Secret Key。这是“只输密码”必然付的代价，
  用户明确以“密码合理”为前提。
- 已有的防线不变：Argon2id 参数（OWASP 最低值）、创建时的
  密码强度提示。强度提示是唯一的护栏，不再加硬性长度门槛——
  用户是决策者，产品不替他定“多强才算合理”。

## 考虑过的其它选项

| 选项 | 否决原因 |
|---|---|
| A. 把 Secret Key 缓存在本地（1Password 的存法） | Secret Key 就要以某种形式落盘，等于多一个要保护的秘密；第二份包装让 Secret Key 永远不离开恢复套件，更干净。 |
| B. KDF 里 Secret Key 改可选 | 会改动 Secret Key 那份包装本身，破坏与引导包的兼容；第二份包装只加不改，老库头仍能打开。 |
| C. 维持现状（每次都要 Secret Key） | 用户已明确否决：没人每天记一长串。 |
| D. 只靠生物识别解决日常解锁 | 没有生物识别的设备（或用户不想用的）仍被卡住；密码-only 是不依赖硬件的底线。 |

## 取舍与后果

**得到：**

- 日常解锁只输主密码；Secret Key 回到它本来的位置：新设备和救急。
- 老库无缝迁移：一次带 Secret Key 的解锁即完成，用户无感。

**付出：**

- 本地文件抗离线猜测的能力从“密码 + 128 位 Secret Key”
  降为“主密码 + Argon2id”。主密码弱，库就弱——这是写进
  ADR 的明确代价，不是疏忽。
- 库头多一个字段；`open`/`create`/`adopt`/`change_password`
  都要同时维护两份包装（测试覆盖）。
